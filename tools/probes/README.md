# probes

**这些探针是按需工具，不是每次改动的作业。** 2026-10-21 起（用户 m53748「很小的改动你都进行大范围的
测试」、m54271「希望把时间都花在开发上，而不是不停歇的测试」）项目的默认是**不跑测试**，只有四个触发才跑：
改了判据／守卫／牙本身（只拆那一条：`--teeth <名字>`）、改了某模块的核心行为（跑那个模块自己的那条）、
用户说「验一下」、发版（全套 + `tools/verify.py --tier C`）。日常自检只有 `py_compile`、模块能 import／
`--help` 打得开、改到面板再拍一次 `tools/_flet_smoke.py`。细则在 `AGENTS.md` 的「改动怎么验：带牙 + 按需」。
下面的表仍然是**判据归属的索引**（哪个判据归谁管、有几颗牙），这一点没变。

**夹具（`evidence/`）不随仓库分发。** 那些帧全是游戏画面，版权归原方；仓库里只放代码。\
克隆下来直接跑探针会因为读不到 `evidence/nav/…` 而报错——要么先跑几局把帧拍下来、按下面各条的
口径钉住（`tools/evidence.py build --only nav` 会重建 `MANIFEST.json`），要么就当这些探针是
作者本机的取证工具。

Thirty-five of these are regressions with a verdict (`mtdiag` among them -- it needs the emulator's
adb up but touches nothing); the rest of the directory is forensics -- the measurements the rules in
`tools/` cite, kept so a claim can be re-checked instead of re-guessed. They are listed at the
bottom; the ones that need input say so in one line instead of a traceback (`fieldcal`, `hudmap`,
`votediag` when handed nothing; `burst`, `gatecheck`, `vidframe`, `vidscan`, `vidstall` always).
Two of those -- `hudmap` (a run log plus a chart's hits) and `vidscan` (a `--record`ed mp4) -- are
analysis tools rather than regressions: they answer a question about one specific round, they never
print a verdict, and the four `--record-counters` AVIs they were written against are no longer in
the tree (only `research/runs/<tag>.stairs.json` and `*.counters.jsonl` survive them).
