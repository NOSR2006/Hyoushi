## 文案口径（面板上的字）
- **一律书面语**（2026-10-10 用户 m15780：「能不能提高文字的专业度，很多句子都太口头了，要注重书面表达」）。范围 = 面板界面上的字：标签、tooltip、提示语、空态文案、日志行；不含仓库文档、不含给用户的回复。规则原文在 `AGENTS.md` 的「文案（面板上的字）」那节。
- 口径：用「本局 / 该 / 尚未 / 已 / 请 / 不支持 / 终止 / 时长 / 轮次 / 重试」这类书面词，不用「搞定 / 弄 / 咋 / 吧 / 说白了 / 慢慢翻 / 开打 / 杀掉 / 白改」这类口语词；一句一件事，不靠感叹号和括号补语气。**只动给人看的字**：路径、选项名（`--live-push-cap`）、状态键、日志标记（`#ATSELECT#`）一个字都不许改。
- **改文案要连带扫钉子**。本轮（91 条 + 1 条漏网）真的扫到两处：`fletpanel.py:984` 的判据 `"两侧放开" in t1` → 改名「双向放开要说出来」并把期望串改成 `"双向放开"`（文案成了「（「正推限制」已关闭，双向放开）」）；`fletpanel.py:1067` 的 `alarms()` 过滤子串 `"撞到边界"` → `"已达边界"`（文案成了「链路标定已达边界」）。**只按整条旧串扫是扫不到这种片段的**（一次性脚本 `research/experiments/uiformal.py` 收尾只报「整条旧串还留在别处：0 处」）⇒ 改完必须**真跑一遍受影响的探针**，不能只信脚本的收尾统计。
- **「有没有被挤折行」不能靠眼睛判**（本会话的模型没有图像输入、`modlens` 也没配 vision provider）：`research/experiments/copyshots.py <tag> [页名…]` 借 `fletviewcheck._fixture`/`_run_child` 拍八张（`start`/`multi`/`log_empty`/`settings` × 浅深）到 `research/frames/copy<tag>_*.png`，`research/experiments/copyband.py` 比两张并打**行带**（行带高度 ≈ 一行字，出现 h ≥ 50 就是折行）。本轮读数：`start_light` 差 564 px（y592..609 h18）、`multi_light` 8582 px（三带 h18/h19/h19）、`log_empty_light` 2575 px（h19）、`settings_light` 4884 px（h19），浅深同型 ⇒ **没有一条被挤折行**。
- **拿旧稿当对照要先把新稿锁住**：`uiformal.py --revert`（反向、倒序、replace-all、容忍命中数不符）写完盘之后，正向 `--go` 会因为那几处计数不符而拒绝写盘，盘上会留下一份「大部分旧、五处新」的混合稿 —— 事后必须用 `--force --go` 收敛回新稿，并以**源码哈希**核对（本轮核对后 `py_compile` 0、`import flet_gui` ok、`fletviewcheck` 十二面全 0 px）。

- **缺数据的行两个方向都排在最后**（用户 m11595 报「从大到小排序时占位符总是排在最前面」）：次序由 `core.hist_order(rows, col, desc)` 一处定 —— 先把有值的与缺数的分成两堆，有值那堆按方向排、缺数那堆原样接在后面。**不能**用 `(v is None, v)` 当 key 再 `reverse=`：哨兵会跟着 reverse 一起翻，降序时缺数行全跑到最前（这就是那个 bug）。`hist_value` 缺数仍是 `None`（不参与比较），混类型列（文本列里混进数字）在 `hist_order` 里退回按 `str` 排，不让一列脏数据把页面打白屏。回归 `tools/probes/paneldata.py`（八条 `GOLDEN_ROWS` 的 `cells` 摘要按新实现重钉 + 「没读数恰好印 `—`」+ 「判定列写 `成功`、不写破折号」+ 「`hist_order` 两个方向都把缺数放最后」+ 三颗牙：把「留空」写法放回去必须露空格、把「判定列写破折号」写法放回去必须露出来、把「哨兵 + reverse」写法放回去降序时缺数必须跑到最前）与 `tools/probes/fletpanel.py` 第 6 关（真窗口里按 漏键 降序／升序各排一次，缺 `non_perfect` 的那两条夹具行都必须在最后）。

## 行为与状态
- **关窗与重启都先问一句，说「好」才 `force_kill` 收掉正在演奏的 `run.py`**：Windows 上父进程退出不会带走子进程；实测孤儿能一直跑下去，还会让新面板以为自己是空闲的。

## 过渡动画（实现）
- 开关在设置页「面板」卡（状态键 `motion`，缺键当开）：关掉就是立刻到位、不做入场动画，**终态与开着时逐像素相同**。
- **六个装置**（换页是 M3 fade-through，淡出与淡入各一档，合计 100 + 200 = 300 ms = `medium2`），时长与缓动全由 `m3_theme` 的 `MOTION`／`MOTION_DURATION`（16 档）／`MOTION_EASING`（7 档）供给；六处现场都过 `self._motion()`，九个动画函数（含退场那两路）里不许有字面量时长。`fletgui.py` 第 9 关钉住（令牌逐格对规范、装置恰好是 `page_out`／`page`／`progress`／`phase`／`flash`／`card`／`card_out`（七个档位、六个装置，「卡片进出场」分进出两档）、两拍相加 = `medium2`、`PAGE_SCALE_IN` = 0.92）。
- 换页照 Flutter 的 `fade_through_transition`：旧页 100 ms `emphasized_accelerate` 淡到 0 → 换内容、**不带动画**落到 `PAGE_SCALE_IN`(0.92) → 200 ms `emphasized_decelerate` 淡入并放大回 1.0（官方那句：缩放只给进来的元素）；`self._page_seq` 让连点页签时在飞的那次作废。关掉动效时先清 `animate_opacity`／`animate_scale`、把 `opacity`／`scale` 拉回 1.0 再换 `content`，终态与开着时逐像素相同。
- ① `_fade_page` 换页签淡入（`medium2`／`emphasized`）；② `_fade_phase` 状态行淡入 —— **文字立刻到位**（`_set_phase` 里就换好），这一拍只负责让它看得见：先把 `animate_opacity` 摘掉、**不带动画**地压到 0（起点必须在这一帧画出去），下一帧再挂 `MOTION["phase"]`（150 ms）淡回来，带 `_phase_seq` 作废旧拍（把换字押在淡出的第二拍上过会整局不动，`fletfly.py` 第 4 关抓过；2026-10-07 之前这里是「挂着动画压到 0、等 `AWAIT_FRAME`(60 ms) 就抬回 1」，补间刚走到四成就被反向、`phase` 这档令牌等于没用上，而终态一样 ⇒ 只量终态的探针看不出来，现在 `fletpanel.py` 第 1 关按两拍采样）；③ `_tween_progress` 进度条 16 ms 一步、向上走 `1-(1-t)^3`、向下直接落 —— 收尾那一跳必须**作废在飞的补间**，否则刚落的 0 会被抬回 1.0；④ `_flash_tick` 新结算行闪一下（`extended1` = 700 ms）；⑤ `card` = 250 ms `emphasized_decelerate`，用在摘要卡、三处空态、封面槽与**「最近演出」卡整卡进场**的 `_fade_in` 上（`_fade_in` 的第一拍也先把 `animate_opacity` 摘掉、**不带动画**地压到 0，第二拍才挂回 `MOTION["card"]` —— 三处空态、封面槽与曲中提示行都是「先前不透明、藏起来又显示」的控件，不摘的话 1.0 → 0 自己就是一段补间，60 ms 后抬回 1.0 时它才走到两三成，看着是闪一下而不是淡进来，与 `_fade_box` 同型）；换挡那一下还有一次整页 `_fade_reflow`（0.35 → 1.0）。⑥ 整块内容被换掉的地方（结算表的筛选／排序／改条数三条路径、运行日志页点筛选 chip、选曲列表的换分类／换排序／翻方向／清空搜索）走 `_fade_box` 那一次两拍淡出淡入 —— 行数一变的高度跳高没有任何插值，靠它盖住；打字搜索、点行选中、开截图、拖窗口换列集都不淡（`reload_songs(fade=True)` 只给离散那几路，`_on_search` 不许传）；⑦ 曲中提示行从藏到显时走 `_fade_in`（`card` = 250 ms，与三处空态同一档，第一拍同样摘掉 `animate_opacity`、不带动画地压到 0），收起来仍瞬时 —— 高度得立刻还回去（与 `_toggle_empty` 一个道理）。
- **框架自带的动效**（我们没写、但确实在动，只作参考、不当判据）：对话框进场 150 ms（`dialog.dart:1853`）、SnackBar 250 ms（`snack_bar.dart:28`，我们只传显示时长 4000）、滚动条淡出 300 ms（`scrollbar.dart:17`）、chip 按下 75 ms（`chip.dart:999`）、以及一批「样式变化」的补间（`icon_button`／`list_tile`／`navigation_rail`／`segmented_button`／`button_style_button`）默认取 `kThemeChangeDuration`／`kThemeAnimationDuration` = **200 ms**（= `short4`，与我们的 `MOTION["page"]` 同长）。这些常数来自 Flutter stable 源码（`%TEMP%\bang_flutter\` 那份缓存），而面板跑的是 **Flet 1.0.3 自带的 Flutter**、版本未必相同 ⇒ **这是 Flutter 的选择，不是 M3 的规定**，不许拿去当判据（M3 只规定时长与缓动令牌，组件内部怎么补间是框架的事）。
- 「最近演出」卡的**退场**也是淡的（用户 m09421）：`_fade_out_card` 先按**退场档** `MOTION["card_out"]`（`short4` = 200 ms、`emphasized_accelerate`）淡出、`await` 完才 `visible=False`（从前借的是控件自带的**进场**档 `card`，`emphasized_decelerate` 淡出等于「慢慢停下」，与规范「进屏幕 decelerate／离开屏幕 accelerate」那对是反的）（`_fade_out_row` 管行数变少的单独一行）。两条都靠**那张卡自己的** `rc.seq`／`rc.hiding`／`r["out"]` 作废在飞的那次（m10950 之前是 `Panel` 上的 `_recent_seq`／`_recent_hiding`，只有一张卡时够用；现在两张卡各持一份，谁也不作废谁）—— 连续拖窗口时「淡出没播完又要显示」必须能撤销，否则卡片会停在半透明或隐藏上。**Flet 的隐式动画只管 `opacity`／`offset`／`scale` 这些绘制属性，布局高度没有插值**：让出高度那一帧仍是瞬跳（框架边界，不是取舍）；行数变少与整卡退场都走这条路，`fletgui.py` 第 11 关在钉（含 sleep 必须早于 `visible=False` 的顺序）。

## 探针与截图口径（面板相关）
- **截图必须与鼠标在哪儿无关**：窗口可能正好开在鼠标底下，Flutter 会给光标下面那个控件弹默认 tooltip 并把它拍进基线（曾让两张 `start_*` 基线各多一块 534×38 的反色方块，而两张新图互相逐字节相同 —— 脏的是基线，不是渲染）。所以 `page.add` 之前用 `_flet_smoke.strip_tooltips` 把整棵控件树的 `tooltip` 摘干净（靠 `dataclasses.fields()` 通用地走；tooltip 只在悬停时画，静止帧一个像素都不变），`fletviewcheck` 与 `_flet_smoke` 两条拍照路径都走它；摘了 0 个或摘完还剩就 `SHOOT-FAIL` 硬退。
- 出口早闸 `_flet_smoke.audit` 的尺子是**单片最大**的近似灰颜色（`0xA8..0xD0` 且三通道差 ≤3，与 `fletgui.py` 第 5 关同一把）：真正的 ErrorWidget 是平色大块（实测约 1.64 M px）照样拦得住，灰字的反锯齿不会被误报；`fletgui.py` 第 10 关另有一条「2400 px 孤立反锯齿灰字必须放行」。
- **探针自己不许留孤儿**：`fletfly.py --child` 末了是 `os._exit(0)`（不陪 Flet 做退场），而 Flutter 客户端是**另一个进程**，所以收尾必须先把窗口真的关掉再硬退 —— `fletgui.py` 第 8 关由父进程跑前跑后各数一遍 `tasklist` 里的 `flet.exe`（拆掉关窗实测每跑一次正好多留 1 个 ~170 MB 的客户端；攒到 6 个会把 `maskfast` 挤成 `ArrayMemoryError`、让 `fletviewcheck` 的子进程产不出截图）。`__end__` 写在关窗之前（关掉最后一个窗口会把 python 一起收走），子进程的 `returncode` 也一并进判据。
